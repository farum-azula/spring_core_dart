## 0.10.0

- **Debug builds only by default:** a debug tool whose build switch is not set (the panel, the frame meter, the motion switch, the Flutter tab, the task manager, the timeline, the graph and its layers, the log export) is in debug builds only; a profile build has it only with its switch `true`, so a profile measures the app without the tools. The console stays out of every build unless `spring.flutter.debug.console.enabled: true`, which puts it in every build, release included.
- `DebugCorner` (top-left, top-right, bottom-left, bottom-right), shared by `spring.flutter.frame-meter.position`, `spring.flutter.debug.console.position` and the debug overlays; `FrameMeterPosition` and `DebugOverlayCorner` are deprecated aliases of it. `DebugLayout.phoneWidth` (600) is the phone width the console and the panel share.
- The application graph's builder widgets are one registry: `DebugGraphWidgets.builders` (Flutter's, `DebugGraphBuilders.flutter`, plus each registered `DebugGraphBuilders`), `DebugGraphWidgets.addBuilders` / `removeBuilders` (a bean's `postConstruct` / `preDestroy`), `isBuilder`, `isBuilderType`. The Flutter starter no longer names the signals starter's `Watch` and `AsyncView`; `WidgetsGraphLayer.builders` is gone.
- `DebugValueText` is the one way the debug tools write a value: `shortOf(value, max:, objectText:)` (a shorter text; an object by its own `toString()`), `DebugValueKinds` registered by a starter (`DebugValueText.addKinds` / `removeKinds`) asked before the built-in kinds, `objectKind`. A string or `Uri` holding an address is masked (`SecretNames.maskedUrl`), and so is the value of a map entry whose key looks secret.
- The graph's layer colours: `DebugStyle.graphLayer(id, orElse:)`; each layer gives its default in `colorOf` (beans green, widgets cyan blue, signals orange). `DebugStyle.graphBeans` / `graphWidgets` and the `graphBeans` / `graphWidgets` / `graphSignals` fields of `FlutterDebugThemeProperties` and `ConfiguredDebugTheme` are gone (`graph-beans`, `graph-widgets`, `graph-signals` are read as `graph-<layer id>`); the signals starter's layer asks `graphLayer('signals', orElse: command)`.
- `spring.flutter.debug.graph.beans.enabled` is gone: the beans layer is in the build by `spring.flutter.debug.graph.layers` only, and in a running app follows its view (`spring.flutter.debug.graph.enabled` for the Graph tab, the console for the `graph` pane). `spring.flutter.debug.console.slide` and `DebugConsole.slide` are gone: `slide-duration: 0` shows and hides the console at once.
- The widgets layer, the debug themes and the overlays' dock follow their view in a running app: none with the panel (or the Graph tab) or the console turned off, no dock without a debug overlay. The console's `isolates` and `timeline` segments are in the build only with the task manager and the timeline (`spring.flutter.debug.isolates.enabled` / `timeline.enabled` are their parents), and `IsolatesSegment`, `MemoryConsoleSegment` and `TimelineSegment` take their source as required.
- The application graph: a hot branch cools as its rebuilds leave the window, with no card open; hiding or showing a layer stops or starts that layer alone, and a hidden layer is told nothing of it is selected; a collect of the same structure replaces the nodes the cards read, without a new layout; a tooltip follows its plate across a new scene; a chosen group that is gone filters nothing, and the Groups control stays while groups are chosen; an opened row of a card stays with its row and shows its value now.
- The Logs tab stays at the very bottom with rows of many heights (jumped again while the end moves, the list not reversed, so long-press selection keeps working); Clear while scrolled up (here or in the console) drops the held records; the marks of records the buffer dropped no longer count.
- The network recorder masks every address in a recorded error's text, in `Location`, `Content-Location` and `Link`, and the WebSocket subprotocols that carry a credential (`NetworkMasking.text`, `NetworkMasking.protocols`); the Size block masks the addresses it lists (`PageResource.masked`). The method chips of the Network tab are the methods recorded (`DebugNetworkFilter.methodsOf`, `methodOrder`; `methods` is gone), and `TRACE` is documented as a method that reads.
- `spring.flutter.debug.network.body-budget` (4MB by default): the bytes of bodies and payloads kept in all; past it a new one keeps its size only. `body-limit` is capped at 1MB (`DebugNetworkJournal.maxBodyLimit`). On the web, the `PerformanceObserver` of Resource Timing is connected only while a recorded request waits for its timing (`ResourceTimingSource.observe`, `ResourceTimingReader.done`).
- The log export no longer falls back to the clipboard: on a phone without a `DebugFileExport` of the app's it tells what to add (`DebugFileExports.noneAvailable`); `ClipboardDebugFileExport` is used only when the app registers it.
- `WidgetAwareBuildTracker.attachTo(rebuild, context)` and `WidgetBuildTrackings.context` name the `BuildContext` `context` (was `widget`).
- The debug panel's Isolates tab opens with the app's memory, a card per number large in the debug theme's number colour with a chart of the last three minutes and a muted line of what it is: natively the process's resident memory and the Dart heap (used, capacity) from the VM service, connected to only while the tab shows and "not available" in a release build; on the web the JavaScript heap (used, total, limit; "this browser does not tell" outside Chromium); everywhere Flutter's image cache (bytes and images of the maximum, live, pending). On the web a size block follows, from Resource Timing: what the page transferred and decoded in all, by kind (`code`, `fonts`, `images`, `other`; `pageResourceKinds`) and the ten heaviest, a cross-origin download without `Timing-Allow-Origin` marked `hidden`; natively it points to `flutter build --analyze-size`. The console's `memory` segment (`memorySegment`, `mem 182 MB · img 34 MB`, the JavaScript heap on the web) is a module of its own (`springBootStarterFlutterDebugConsoleMemoryAutoConfiguration`), in the build only when `segments` names `memory` or holds `*` and the task manager is in the build. Nothing is read while neither shows. `DebugMemoryWatch`, `MemoryFigureSource` (a card of the application's own), `DebugIsolates.memory`; a part of a `DebugConsoleValue.of` shows its own label.

- The debug console slides in from its edge when shown and back out when hidden (220 ms), from the top in a top corner and from the bottom in a bottom one; pressed again while it slides out, it comes back from where it is. It slides in only when shown, not when built again while it stays (the debug panel closed, the console moved), and hidden while not on screen (the panel's Overlays tab) it is hidden at once. `spring.flutter.debug.console.slide-duration: 0` shows and hides it at once, with no animation in the tree; `DebugConsole.leaving`.

- The application graph: a tap on a plate selects it and lights its chain, a double tap (double click) opens its card, open with its rows, and closes it; a lane folds by a tap on its title (`[-]` / `[+]`), not from a card. A card's line may list nodes under it (`DebugGraphDetail.links`, `DebugGraphDetailLink`): a bean's card lists what it depends on and what uses it, each with how it is injected (`@Lazy`, `provider`, `@DependsOn`, `in a collection`), a widget's card the beans it holds; a row whose node is on the graph selects it (the view does not move), one that is not shows dimmed with why (`framework`, `widget`, `not shown`). - A widget's card in the application graph shows its values: a `properties` block (the widget's) and a `state properties` block (its `State`'s), from Flutter's diagnostics in a debug build (`DiagnosticsWidgetProperties`) and the public fields the generator reads (`FieldWidgetProperties`, `DebugWidgetFields`, the lazy bean `debugWidgetFields` of the application's debug part); sources asked in turn (`WidgetProperties`, `WidgetsGraphLayer.properties`, the application's beans first). Values short (`List(6)`, `Map(2)`, a type name in place of `Instance of …`, strings cut), a row marked `▸` opening into the whole value on a tap (`DebugGraphDetail.more`), secret-looking names masked (`SecretNames`). A card's lines may be grouped in titled blocks (`DebugGraphDetail.section`). Read when a card opens and at most once per walk of the tree after.

## 0.6.2

### Changes

- Files of the app (0.6.2): `FileTemplate` (beans `fileTemplate` and `platformFileStore`, each only when the app declares none) writes and reads text, bytes and objects (JSON through the `ObjectMapper`) in the places `support` (default), `cache` and `documents` (`files.cache.write(...)`), with `exists`, `delete`, `list(prefix)` and `modifiedAt`. Writes are atomic (temporary file, then rename), paths stay inside their place (`..` and absolute paths are refused). `temp((file) async {...})` and `tempDir(...)` give a unique temporary file or folder deleted after the block (an error too); `createTemp()` leaves the deleting to the caller; leftovers are removed when the context closes and, for runs that died, at the next start (`<system temp>/spring/<run id>/`). The bytes go through a replaceable `FileStore` (`LocalFileStore` on `path_provider`'s directories, IndexedDB in a browser; temporary files in memory there, with no path). New dependency: `spring_web_dart` (see below).
- One set of app directories (0.6.2): SQLite's `location` and `FileTemplate`'s places share one mapping. On Windows `support` is `%LOCALAPPDATA%\<company>\<product>` (the machine's own) for both, and `cache` is the `cache` folder inside it (`path_provider`'s cache directory is the local root itself, so it would have been the same folder as `support`); the other platforms are unchanged.
- The theme from a URL (0.6.2): `spring.flutter.theme.themes.<name>.source` (an `https` URL or `github:owner/repo/path@ref`), `source-sha256` and `refresh`. The theme is cached through `FileTemplate` (`support`, `spring/themes/<sha256 of source and pin>/theme.yml` and `meta.json`) and survives restarts: without `refresh` downloaded once and read from the cache for ever; with `refresh` the cache is used at once and read again in the background (`If-None-Match` / `If-Modified-Since`) when older, and a new theme is shown live. Another `source` or `source-sha256` downloads again; caches of sources no longer configured are removed at start; offline or on any error the cache, else the theme of the app's own files; size limit 1 MiB, timeout 10 s, `https` only (redirects too). Only the theme's keys are taken from the file, the rest is ignored with a warning. `SpringThemes.applySource` sets the properties of one such theme. The HTTP client is the app's `HttpTransport` bean or `spring_web_dart`'s platform client: the package depends on `spring_web_dart` now.
- The whole theme (0.6.2): `spring.flutter.theme.components.*` sets every component theme of `ThemeData` (48: app bar, badge, banner, bottom app bar, bottom navigation bar, bottom sheet, the buttons, card, carousel, checkbox, chip, data table, date and time pickers, dialog, divider, drawer, dropdown menu, expansion tile, icon themes, input decoration, list tile, menu, menu bar, menu button, navigation bar, drawer and rail, popup menu, progress indicator, radio, scrollbar, search bar and view, slider, snack bar, switch, tab bar, text selection, toggle buttons, tooltip) with Flutter's own property names in kebab case, read by the type of the value (color, shape, border side, insets, size, constraints, text style, icon theme, number, elevation, enum, duration, mouse cursor, alignment, decoration, input border); `cupertino.*` sets `CupertinoThemeData` (primary and contrasting colors, backgrounds, handles, `text-theme.*`). Every `WidgetStateProperty` takes one value or a map per state (`default`, `hovered`, `focused`, `pressed`, `dragged`, `selected`, `scrolled-under`, `disabled`, `error`; the strongest wins in that order of strength: disabled, error, pressed, dragged, hovered, focused, selected, scrolled-under, default). Colors take an opacity (`primary@12%`), shapes a map (`type`, `radius`, `side`), text styles a map over a base style. An unknown component or property, or a wrong value, stops the start naming the valid ones, with a "did you mean". The 16 earlier components keep their keys. One fix: when `button` and a button kind (`filled-button`, ...) set the same property, the kind's value now wins (it was the shared one). The component reference of `docs/configuration.md` is generated from the mapping and a test keeps it in step.
- `ThemeKeyReader` (`context.theme` of the generated `lib/spring_keys.dart`): the typed theme keys read the theme shown now through `SpringTheme.of(context)`. See `spring_core_dart_generator`.
- The theme files and the property-file lookup use `resources:` (`resources:themes/*.yml`); `classpath:` still works with a warning (see `spring_core_dart`).
