## 0.7.0

- Smaller and faster generated code (`spring_core_dart` of the same release is needed). Introspections of classes without type parameters, and the `BeanMethod`s of `annotatedMethods`, are constants: their closures are top-level functions (`_$get3`, `_$set4`, `_$create5`, ...), and a property's `type` is left out when its `typeInfo` gives it. Constructors and annotated methods are called directly instead of through `Function.apply` (an absent optional argument gets its default through `argumentOr`; `Function.apply` stays where a default or a type cannot be written, for a parameter typed by a type parameter of a generic base class such as `save(E entity)` of `Crud<E>`, and for the methods expressions call). A call with wrong arguments now fails with the cast's `TypeError` (`type 'String' is not a subtype of type 'int' in type cast`) instead of `Function.apply`'s `NoSuchMethodError`. Proxies mix in `AdvisedWrapper` / `AdvisedSubclass` instead of writing the `Advised` members, and hold the invoker in `aopInvoker` (a member of that name in a proxied class now fails the build, like `aopTarget`). `MethodSignature.of(name, target)` shares one `AopTarget` per proxy and leaves out the declaring type when it is the bean class. `types:` is left out when it is `[T]`. A pruned bean gets `const AopProxyFactory.pruned(knownAdvisors: ...)` without the text.
- `aop_prune` also prunes subclass proxies (the bean is then created as its own class) and, in the proxies it keeps, the members no advice can match: a wrapper forwards them to the bean, a subclass inherits them. Such a member cannot be intercepted by advice added at run time: `Advised.addAdvisor` on such a proxy, and an advisor bean the build did not see, fail instead (see below). `aop_prune: false` keeps everything, as before.
- Defaults and initial values `double.infinity`, `double.negativeInfinity` and `double.nan` are written as such (they were written `Infinity` and `NaN`, which do not compile, in proxies too), and constant collections keep their type arguments (`const <int>[]`, also when empty; an initial value takes them from the field, `<num>[1]` for a `List<num>`; a map gets both or none, `const <String, Object>{...}` was written without them). A method of a generic base class described for a subclass gets `Object?` for the base class's type parameters, at any depth (`List<E>` was written as it is and did not compile; `Map<String, List<E>>` is a `Map<String, List<Object?>>`).
- The `lib/` modules of a starter (a library package with `lib/spring_auto_configuration.dart`) leave to the application the proxy classes only its aspects can match (no annotation an advisor may match, no pointcut of the module): `AopProxyFactory.deferred(signatures: ...)`, without the class. The `@SpringBootApplication` output finds them in the starters' modules (those their auto-configuration library and the application import) and writes the classes of those its pointcuts may match (all of them with `aop_prune: false`) into `BeanModule.aopProxies`; the starters' properties classes no longer bring 25 proxy classes into every application. A starter defers a proxy only when no advice of the package (its other modules, its auto-configuration) nor of the auto-configurations it builds on may match the bean, so a context of the starter's modules alone keeps working; a `bean(...)` pointcut of the application matches such a bean by its aliases and qualifiers too. A context built without that output fails at startup if advice matches such a bean, saying so, instead of skipping it.
- New option `dart_defines_exclude`: property name prefixes left out of `springApplication.dartDefines` (both forms).
- `dart_defines_exclude` prefixes match whole segments with relaxed binding: case-insensitive, `-` and `_` inside a segment ignored, an environment-variable prefix (`SPRING_DATASOURCE`) matching the dotted names too, and a property's dotted and environment forms left out together. A trailing `.` or `[` is ignored; a blank entry, a `*` wildcard or a non-string entry fails the build.
- A package that depends on `spring_boot_dart` but not on `spring_core_dart` (a starter, an app) gets the container API through `package:spring_boot_dart/spring_boot_dart.dart`, which re-exports it, instead of a direct import of `spring_core_dart`: pub.dev refuses a package whose `lib/` imports a package missing from its `dependencies`.
- Proxy pruning keeps more where it cannot be sure. An annotation an advisor names (`AnnotationMatchingPointcut<A>`, an `annotationTypes` list) keeps the beans and members carrying it whatever its package (one of `spring_core_dart` or `package:meta` was treated as advising nothing), and a class-level one keeps every member. Advice registered in code (an `@Import`ed registrar, a `BeanFactoryPostProcessor`) is not read by the build: the pruned and partial proxies carry the advisors it knew (below), and the startup fails when another one is registered. The classes a nested module `@Import`s are read for advice too. The library beans whose proxy class the application writes keep the members an advisor's annotations may match, as the application's own beans do.
- Pruned and partial proxies carry `knownAdvisors: _$knownAdvisors<n>` (one constant per module: the sources of the aspect and advisor beans the build read, and `package:<name>` for each auto-configuration package it read), so the context fails at startup when another aspect or advisor is registered, and advice added at run time to a partial proxy fails instead of skipping members (`spring_core_dart` of the same release is needed).

## 0.1.7

- an error in the sources never removes or changes an existing `*.beans.dart` (`build_runner watch` while typing no longer deletes and regenerates it on every keystroke): while a scanned library has syntax errors the builder skips generation, writes the existing file again unchanged and logs one warning per output until the next successful generation; a generator error (private type, unknown bean, bad annotation, cycle, ...) keeps the file too and is reported with `log.severe`, so `build_runner build` still fails; without an existing output (a cold build) both fail as before. `SpringBuilder` takes an optional `readExistingOutput` (tests inject it) and its constructor is no longer `const`
- `@ComponentScan(includeFilters:, excludeFilters:, useDefaultFilters:, lazyInit:)` evaluated at build time: `Filter` by annotation (also its subclasses), assignable type or a regex on the class name makes classes beans without `@Component` (abstract ones skipped) or keeps them out (excludes win); `useDefaultFilters: false` scans only the includes; `lazyInit: true` makes every scanned bean (components and their `@Bean` methods) lazy unless `@Lazy(false)`; a filter without the argument its type uses or with an invalid pattern fails the build (needs the matching `spring_core_dart`)
- `@Bean` methods, `@Autowired` members, `@PostConstruct` / `@PreDestroy` and `@EventListener` methods of superclasses and mixins are found (Spring scans the hierarchy; mixin lifecycle methods run in Dart's linearization order); the members of a generic superclass (`UserService extends BaseService<User>`) get the type arguments substituted; an inherited static `@Bean` method is called on its declaring class; an override without `@Bean` of an annotated superclass method still creates the bean
- breaking: a private bean class, `@Bean` return type, injected type (also as a type argument), event type or default value (a private function, class or constructor) fails the build with a message naming the declaration, its library and the fix, instead of a generated file that does not compile; the full-mode `@Configuration` errors no longer suggest `proxyBeanMethods: false` for private types (it would not help)
- AOP argument binding: an advice parameter named in the pointcut (`@annotation(timed)`, `@within(timed)`, `@target(timed)`, `this(proxy)`, `target(bean)`, `args(id, ..)`) receives the bound value, checked against its type; `@AfterReturning(returning:)` / `@AfterThrowing(throwing:)` name the value parameter; advice and `@Pointcut` methods of an aspect's superclasses and mixins are inherited; a parameter the pointcut does not bind, or a bound name without a parameter, fails the build (needs the matching `spring_core_dart`)

- `@PostConstruct` / `@PreDestroy` methods and `@Bean(initMethod:, destroyMethod:)` may return a `Future` (awaited by the context's `refreshAsync()` / `closeAsync()`): their callbacks are written as `async` closures (needs the matching `spring_core_dart`); those of a `@Configurable` stay synchronous

- `@Bean` types inferred from the method body: the static type of the returned expression(s) (with type arguments; several returns: their common supertype) registers the definition under the concrete class and its supertypes as well as the declared type, so lookups, `@ConditionalOnBean` / `@ConditionalOnMissingBean`, lifecycle methods and AOP proxies see it before the bean exists
